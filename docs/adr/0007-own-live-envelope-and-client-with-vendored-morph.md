# Monk::Live owns its envelope and a tiny client, and vendors only the morph primitive

Server-pushed HTML that patches an open page already exists as Turbo Streams, htmx's `ws` extension and Datastar, and we still decided not to adopt any of them. Each one brings its own connection ownership and swap conventions, which would have to be reconciled with `Monk::WebSocket`'s per-connection Ractor model and `Monk::Views`' boot-compiled templates rather than sit on top of them. We decided Monk::Live defines its own small JSON envelope (`patch`/`batch`, a CSS `target`, a per-connection `seq`) and ships its own client of roughly 100 lines, vendoring only idiomorph (about 9KB minified, Zero-Clause BSD) for the DOM morph. The Phase 0 client spike is what makes this cheap to commit to: ~60 lines of client plus idiomorph, driven from a real `Monk::WebSocket::Server` in real Chrome, kept focus, typed value and selection, scroll position and an open `<details>` in untouched siblings, kept the same DOM node when the patched region itself contained the focused input, and honored a `data-live-ignore` escape hatch through one callback; a plain `outerHTML` replace lost all of it. The accepted costs are that the envelope and client are ours to maintain and document, that a client-only state change inside a patched region (a `<details>` the user opened) is reset by a morph unless the server HTML carries it or the node is marked `data-live-ignore`, and that the spike covered Chrome only.

## Considered Options

- Adopt Turbo Streams (rejected: about 40KB with its own connection management and Stimulus conventions, competing with `Monk::WebSocket`'s lifecycle instead of layering on it)
- Adopt htmx with the `ws` extension (rejected: mature and small, but its `hx-swap-oob` convention and connection-ownership model would have to be reconciled with Monk's own, for a feature set this proposal only needs a sliver of)
- Adopt Datastar (rejected: newer, smaller ecosystem, and the same "external protocol to adopt" problem, plus a signals layer this design deliberately leaves out)
- Hand-roll the DOM morph too (rejected: focus, selection and input-value preservation are exactly the fiddly cases idiomorph already gets right, and the spike showed they cost one option there)
