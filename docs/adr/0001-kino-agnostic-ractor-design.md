# Kino-agnostic, stdlib-only Ractor design

The framework's stated goal is compatibility with the Kino web server, which offers its own helpers (`Ractor.shareable_proc`, `after_worker_boot`, `on_error`) for building Ractor-safe Rack apps. We considered taking a hard runtime dependency on the `kino` gem to use these directly, but decided instead to build purely on stdlib `Ractor` primitives, treating Kino only as the reference/test server rather than a requirement. The framework's actual product is "a Rack app that is also `Ractor.shareable?`" — a property useful to any Ractor-aware Rack server, not just Kino — and a hard dependency would have blocked running the same app under Kino's own `:threaded` fallback mode or under a conventional server like Puma for local development and testing.
