# Boot-time fail-fast shareability validation

Kino silently falls back to `:threaded` mode when a served app isn't `Ractor.shareable?`, rather than raising an error, relying on an external `kino --check` tool to catch this ahead of time. Since Ractor-compatibility is this framework's core premise, we decided `Boot` (`.freeze!`) should proactively call `Ractor.make_shareable` on the app's routes, `Context`, and helpers, and raise a precise, framework-level error naming the offending route or closure the moment something isn't shareable. We rejected relying on Kino's silent fallback because it would let an app "using this framework" quietly stop being Ractor-safe without anyone noticing — the opposite of what someone would reach for this framework for. `Boot` was already the single deliberate lifecycle moment (see route/Context/state design), so this validation has a natural home and needs no separate step.
