# `<%= %>` HTML-escapes by default

Stock ERB inserts the value of `<%= %>` raw, leaving escaping to an explicit `h(...)` on every interpolation. We decided Monk should escape by default instead, with `raw(x)` as the opt-out, because a framework that renders user data cannot make the safe path the one you have to remember — a single forgotten call is an XSS hole. No dependency was needed for it: stdlib `ERB::Compiler` emits `insert_cmd((expr).to_s)` for every insertion, so pointing `insert_cmd` at an escaping helper is the whole implementation. Two details are load-bearing rather than incidental: `Monk::Views::Raw` overrides `#to_s` to return `self`, because that hardcoded `.to_s` would otherwise downgrade the subclass to a plain `String` and silently strip the already-safe marker; and `h` returns `Raw`, so an explicit `<%= h(x) %>` isn't escaped twice. Because escaping runs inside the worker Ractor serving the request, *which* escape function is part of this decision and not an implementation detail: `ERB::Util.html_escape` raises `Ractor::UnsafeError` from a non-main Ractor (measured on 3.3.6, not yet on 4.0.6), so Monk uses `CGI.escapeHTML`, byte-identical and safe under both — see `docs/ractor.md`. The cost is that a template pasted from an ERB tutorial that emits markup from a variable renders escaped tags — a visible, harmless failure fixed with `raw`, where the opposite default fails invisibly and unsafely.

## Considered Options

- Stock ERB semantics plus an explicit `h(...)` (rejected: a template that looks like ERB behaving like ERB isn't worth making the unsafe path the default one)
- Depending on Erubi for `escape: true`, as Rails does (rejected: a runtime gem dependency for a seam `ERB::Compiler` already exposes; Monk takes none beyond `rack`)
